## 2. 道幅推定の手法と検証

### 2-1. 当初の想定が誤りだった点

道路縁(RdEdg)を polygonize すれば道路ポリゴンが得られる、という前提で開始したが、
**実際に得られるのは街区（建物のあるブロック）であり、道路はその隙間**だった。

証拠: `reports/qc_polygonize.png`（荒川区中心部 500m 四方）
左が道路縁の生線、右が polygonize 結果。着色されたポリゴンはすべて街区で、
道路は白いままの隙間として残る。

この誤りは数値にも表れていた。polygonize 出力の内接円から道幅を出すと
荒川区の中央値が 26.7m となり、実態（住宅地の路地は4〜6m）と大きく乖離した。
細長さ比（面積/内接円面積、周長²/面積）による選別も試したが、
最も厳しい閾値でも中央値15.5mまでしか下がらず、分離できないことを確認した。

### 2-2. 採用した手法

```
道路空間 = 区ポリゴン − 街区ポリゴン群 − 水部
        ∩ （道路縁から25m以内）
```
これを **1m/px でラスタライズ**し、

- `scipy.ndimage.distance_transform_edt` → 各画素の内接半径。×2 が **局所道幅**
- `skimage.morphology.skeletonize` → **中心線**

距離変換は実数を返すため、1m格子でも道幅は連続値として得られる。
道幅が50mを超える画素は非道路（河川敷・大規模空地）として除外。

### 2-3. 解像度の検証

荒川区で 0.5m/px と 1.0m/px を比較:

| 解像度 | 線分数 | 道幅中央値 |
|---|---:|---:|
| 0.5 m/px | 677,569 | 5.0 m |
| 1.0 m/px | 334,235 | 5.1 m |

中央値の差は0.1mで、道幅の推定値に実質的な差は無い。一方0.5mでは23区合計が
3千万線分規模となり処理・保存とも非実用のため、**1.0m/px を採用**した。

### 2-4. 目視検証

`reports/qc_centerline.png`（荒川区中心部 500m 四方）
道路空間（灰）に対して中心線が1本ずつ通り、幹線（緑〜黄, 12〜20m）と
路地（濃紫, 3〜5m）が色で明確に分かれることを確認した。
接続性の破断や、街区内部への誤った中心線の侵入は見られない。

区別の道幅分布は `reports/width_by_ward.csv` を参照。

道幅中央値の下位・上位:

| 下位（狭い） | 中央値 | | 上位（広い） | 中央値 |
|---|---:|---|---|---:|
| 中野区 | 4.2 m | | 千代田区 | 9.5 m |
| 杉並区 | 4.5 m | | 中央区 | 8.9 m |
| 豊島区 | 4.5 m | | 江東区 | 7.7 m |
| 文京区 | 5.1 m | | 港区 | 6.8 m |
| 荒川区 | 5.1 m | | 台東区 | 6.2 m |

**4m未満（緊急車両の進入が困難とされる幅員）の割合が高い区**:
北区 22.1% / 文京区 20.7% / 品川区 20.6% / 豊島区 20.1% / 渋谷区 19.1%

中野・杉並・豊島が狭く、千代田・中央・江東が広いという結果は、
東京の木造住宅密集地域の分布および区画整理・埋立地の履歴と整合する。

### 3-1. 数値の解釈上の注意

- 上表の割合は**線分数ベース**であり、1m格子の中心線1本を1件として数えている。
  中心線は等間隔に生成されるため延長ベースの比とほぼ一致するが、厳密には
  斜め方向の線分が √2 倍の長さを持つ点で偏りがある。延長ベースの集計が
  必要な場合は `geometry.length` で重み付けすること。
- 交差点内部では内接円が大きくなるため、道幅が局所的に過大に出る。
  区単位の統計では平均化されるが、個別リンクの評価では注意が要る。
- 区境をまたぐ道路は、道路縁を「区+50m」で絞っているため両区に重複して
  含まれる場合がある（区別集計では二重計上になりうる）。

## 5. ルーティングネットワーク（05_network.py）

### 5-1. 位相の構築

中心線は1m格子上の2点線分の集合で位相を持たない（23区で約1,700万本）。
端点を整数キーに符号化してノード化し、**次数2のノードだけからなる連結成分＝
1本の街路**とみなして、両端の交差点ノードを結ぶ1本のエッジに縮約した。
連結成分の計算は `scipy.sparse.csgraph` でベクトル化している
（全線分を networkx に入れるとメモリが足りない）。

結果: **694,712エッジ / 総延長 19,586 km**

#### 対角ショートカットの除去

最初の実装ではエッジ長の中央値が **1.4m** にしかならなかった。
原因はラスター細線化の階段状パターンで、斜めの線が
`(x,y)-(x,y+1)-(x+1,y+1)` という直角の並びと `(x,y)-(x+1,y+1)` の対角線を
両方持ち、三角形を作ること。通過点のはずの画素が次数3〜4になり、
街路がすべて1画素刻みに分断されていた。
直角の迂回路が存在する対角線を冗長として落とすことで、
エッジ長の中央値は **1.4m → 23.1m**（荒川区）になった。

### 5-2. 連結性

| | 修正前 | 修正後 |
|---|---:|---:|
| 最大連結成分の平均（ノード比） | 65.7% | **88.2%** |
| 江東区 | 21.0% | 64.8% |

**原因は橋だった。** 道路空間を `区 − 街区 − 水部` で作っていたため、
川や運河を渡る道路が水部の差し引きで消え、橋のたびにネットワークが
分断されていた。運河の多い江東区で最も顕著（最大成分21%）。

基盤地図情報では橋の上にも道路縁が引かれているので、
**道路縁から6m以内は水部でも道路として残す**よう修正した（`BRIDGE_KEEP_M`）。

3メッシュ追加後の23区平均は **87.1%**。

**残る課題**: 江戸川区が53.4%と低い。最大成分と第2成分のX座標範囲が
1474〜7664m / 1920〜7194m と重なっており、河川による東西分断ではなく
**空間的に入り組んだ形で細かく分断されている**。用水路・親水公園が多い区の
特性か、追加メッシュ側の処理に問題がある可能性がある。**未解明で、要調査**。
渋谷区52.3%は鉄道による分断で、こちらは実態を反映している面がある。

### 5-3. コストの検証

区ごとに無作為なOD10組で経路探索し、**4m未満の道路を通る「距離」の割合**を測った
（区間数で測ると経路が長いほど増えるため誤った指標になる）。

| モード | 4m未満を通る距離の割合 | 最短距離に対する遠回り |
|---|---:|---:|
| 最短距離 | 5.8% | — |
| 一般モード | 3.6% | +0.25% |
| 車椅子モード | 2.0% | — |

わずかな遠回りで狭隘道路の通過を大きく減らせており、意図どおりの挙動。
区別の内訳は `reports/routing_qc.csv` を参照。

#### 障壁交差のペナルティを外した理由

当初、水涯線・軌道と交差するエッジに ×50 のペナルティを課していたが、
検証すると **一般モードが最短距離経路よりも狭い道を多く通っていた**
（4m未満を通る距離 137m → 216m、平均幅 10.6m → 8.8m）。

水部や軌道を横断している道路は定義上そこに橋や踏切が架かっており、
むしろ幅の広い幹線である。それを罰したことで経路が裏の細街路に
押し出されていた。

`barrier_cross` は**橋梁・踏切のフラグ**として保持し、平常時のコストには
含めない設計に変更した。橋梁の被災を想定する場合は
`config_weights.json` の `bridge_penalty` に値を入れて
`--stage recost` で再計算する（空間結合をやり直さないので数秒で終わる）。

### 5-4. 倒壊閉塞（地震時モード）

沿道建物が倒壊すると道路に瓦礫が出る。瓦礫の到達幅より道路が狭ければ閉塞する。

```
瓦礫到達幅 debris = debris_max_m × clip(建蔽率 / density_ref, 0, 1.5)
blockage_risk     = clip((debris − width_m) / debris, 0, 1)
```

建物の高さデータが無いため、**250mメッシュの建蔽率を高さの代理変数**として使っている。
`debris_max_m=12.0`、`density_ref=0.45` は**未較正の仮定値**であり、
実務で使うなら東京都の地域危険度調査等で較正が必要。

平常時のコストには含めず、`cost_quake` / `cost_quake_wc` として分離した
（障壁ペナルティで学んだとおり、シナリオ要因を平常時コストに混ぜると
経路が意図せず歪むため）。

#### 区別の閉塞リスク（中央値）

| 高い | | 低い | |
|---|---:|---|---:|
| 豊島区 | 0.58 | 千代田区 | 0.00 |
| 中野区 | 0.55 | 江東区 | 0.00 |
| 目黒区 | 0.51 | 港区 | 0.19 |
| 渋谷区 | 0.50 | 中央区 | 0.20 |
| 品川区 | 0.49 | 足立区・江戸川区 | 0.22 |

豊島・中野・杉並・目黒が上位に来る結果は、**東京都が指定する木造住宅密集地域の
分布と一致**しており、モデルの妥当性を外部から裏付けている。
千代田・江東が0なのは道路が広く（中央値9.5m/7.7m）、瓦礫幅を上回るため。

#### 経路への効果（無作為OD、23区平均）

| モード | 4m未満を通る距離 | 閉塞リスク（距離加重） | 最短距離比 |
|---|---:|---:|---:|
| 最短距離 | 5.8% | 0.212 | — |
| 平常時 | 3.6% | 0.204 | +0.3% |
| **地震時** | **1.6%** | **0.066** | +6.5% |

6.5%の遠回りで閉塞リスクを約1/3に下げられている。

### 5-5. 勾配（DEM）

基盤地図情報の数値標高モデル DEM5A（5mメッシュ・航空レーザ測量）14メッシュを投入し、
エッジ両端の標高差から `slope_pct` を算出した（`06_slope.py`）。
DEM被覆率は全区で99.6〜100%。欠測はDEM5Bで補完している。

#### 短いエッジのノイズ対策

当初は「勾配5%超」のエッジの **76.5%が長さ10m未満**だった（江東区。埋立地で
本来ほぼ平坦）。DEMは鉛直方向に数十cmの誤差があり、2mのスタブの両端で0.2m
差が出ただけで勾配10%になってしまうため。歩行者が受ける負荷という意味でも
数mの区間の傾きは効かないので、**最低15mの基線で測り、0.25m以下の標高差は
DEM誤差として切り捨てる**ようにした。

#### 妥当性の確認

標高と勾配が正しく分離できている:

| | 標高中央値 | 勾配5%超 |
|---|---:|---:|
| 杉並区 | 43.8 m | 2.8% |
| 練馬区 | 40.9 m | 2.8% |
| 新宿区 | 28.8 m | **9.7%** |
| 渋谷区 | 32.1 m | **9.4%** |
| 江戸川区 | **-0.5 m** | 4.0% |
| 墨田区 | **-0.1 m** | 3.1% |

- 標高は 杉並43.8m / 練馬40.9m（武蔵野台地）と 江戸川-0.5m / 墨田-0.1m
  （ゼロメートル地帯）で、山の手と下町の地形をそのまま再現している
- 勾配が急なのは新宿・渋谷・港・文京で、台地を刻む谷（神楽坂・渋谷の谷・
  麻布の坂・本郷台地）の分布と一致する
- **杉並は最も標高が高いのに最も平坦**という結果は、台地の上面が平らである
  ことを正しく捉えており、標高と勾配が独立に機能していることを示す

区別の詳細は `reports/slope_by_ward.csv` を参照。
