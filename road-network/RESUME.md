## サンドボックスの制約（重要）
- **OSMは使えない**: Overpass API / Nominatim ともにプロキシが 403 を返す。
  osmnx を使う設計（旧・方法B）は破棄済み。
- **bashは1コールあたり45秒で強制終了される**。バックグラウンド実行(nohup)も
  コール終了時に殺されるため生き残らない。
  → すべてのスクリプトを **タイル/区ごとに再開可能** な設計にしてある。
  `--skip-done` を付けて同じコマンドを繰り返し叩けば進む。
- **マウント先のファイルは削除できない**（`rm` が Operation not permitted）。
  上書きは可能なので、出力は必ず冪等（同じ入力なら上書きで正しくなる）にすること。
- 中断で **parquetが壊れる**ことがある。03_width.py には `_readable()` による
  自己修復と `_atomic_to_parquet()` を実装済み。他スクリプトにも同様の対処が要る。

### 03_width.py — 完了（全面書き換え済み）
**手法（QCで妥当性確認済み）**
1. 道路縁 RdEdg を polygonize すると得られるのは **街区**。道路はその隙間。
   → `道路空間 = 区ポリゴン − 街区` として道路を得る。
2. 道路空間を **1m/px でラスタライズ**し
   - `distance_transform_edt` → 各画素の内接半径 ×2 = **局所道幅**
   - `skeletonize` → **中心線**
3. 非道路の除去: 水部(WA)を差し引き、道路縁から25m以内のみ採用、
   道幅50m超の画素は除外。

**出力**
- `02_processed/blocks_{区}.parquet` — 街区（中心線生成の入力）
- `02_processed/road_space_{区}.parquet` — 道路空間ポリゴン（可視化用）
- `03_network/centerlines_{区}.parquet` — 中心線 + `width_m` + `ward`
- `03_network/_tiles/` — タイルキャッシュ（`{区}_px1.0v{世代}{tag}_{ti}_{tj}.parquet`）
  区界を更新した区だけ作り直すときは `--tag` で世代を分ける（`--force` は
  区キャッシュ `_edges_*` の再生成用。タイルには効かない）

**結果（QC済み・実態と整合）**
- 23区合計 約1,690万セグメント（1m画素単位の線分）
- 道幅中央値: 千代田9.5m / 中央8.9m / 江東7.7m ←→ 中野4.2m / 杉並4.5m / 豊島4.5m
- 4m未満の割合が高いのは 北22% / 文京21% / 品川21% / 豊島20%
- 荒川区で 0.5m/px と 1.0m/px を比較 → 中央値 5.0m vs 5.1m でほぼ一致。
  0.5mは出力が肥大して非実用だったため **1.0m/px を採用**（`PX` 定数）

### 05_network.py — 完了（全面書き換え済み）
- `03_network/edges_final_{区}.parquet` — **694,712エッジ / 総延長19,586km**
- `03_network/nodes_{区}.parquet`
- 最大連結成分は平均87.1%（渋谷52%は鉄道による分断。江戸川53%は原因未解明）
- 検証済み: 4m未満を通る距離は 最短5.7% → 平常3.6% → 地震1.6%（`reports/routing_qc.csv`）

**実装上の要点（触るときは必読）**
- ラスター細線化の階段状パターンが対角ショートカットを作り、通過点が次数3〜4に
  なってエッジ長中央値が1.4mになる不具合があった。直角の迂回路が存在する
  対角線を落として解決している（`build_topology`）。
- 道路空間から水部を引くと橋が消えてネットワークが分断される。道路縁から6m以内は
  水部でも残すこと（`03_width.py` の `BRIDGE_KEEP_M`）。入れる前は江東区の
  最大連結成分が21%しかなかった。
- **`barrier_cross` にコストを掛けてはいけない。** 橋・踏切は幅の広い幹線なので、
  罰すると経路が細街路に押し出されて逆効果になる（実測で確認）。
  被災シナリオ用に `bridge_penalty` を用意してある（既定0）。
- 中間生成物には世代マーカがある（`03_network/_lines_v2/`, `_topo_v2/`）。
  処理を変えたら `TILE_VERSION` を上げること。上げないと古いキャッシュを再利用する。
